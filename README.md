# MAX Course Agent

Чат-бот в MAX, который собирает учебный профиль студента, показывает расписание и историю обучения, а затем рекомендует подходящие курсы из каталога с помощью LLM. Ответы проходят проверку: бот может рекомендовать только существующие в PostgreSQL курсы.

## Основной сценарий

1. Пользователь открывает бота в MAX и отправляет `/start`.
2. Подтверждает номер телефона и заполняет профиль либо выбирает демонстрационный профиль.
3. Открывает профиль, расписание или историю обучения.
4. Задаёт вопрос, например: `Что пройти по SQL после базового курса?`.
5. Агент извлекает тему, находит кандидатов в каталоге и возвращает объяснение с кнопкой «Добавить в план».
6. Пользователь добавляет курс и отмечает прогресс в меню бота.

## Архитектура

```text
MAX API (long polling)
        |
        v
Python bot + AI agent  --->  Ling 3.0 Tiny Q4_K_M (llama.cpp)
        |                              |
        v                              v
PostgreSQL 18 + pgvector <--- Qwen3 Embedding 0.6B Q4_K_M
```

- `bot.py` — MAX API, регистрация, меню и пользовательские сценарии;
- `agent/` — маршрутизация вопросов, поиск курсов, генерация и защитные проверки;
- `app/` — запросы бота к базе;
- `migrations/` — актуальная схема, тестовые профили и расписание;
- `database_recommed.sql.gz` — сжатый исходный каталог курсов;
- `tests/` — модульные и интеграционные тесты.

## Запуск в Docker

Нужны Docker Desktop/Engine с Compose v2 и токен MAX-бота. Ключ LLM API не нужен: обе модели локальные.

```bash
cp .env.example .env
# заполнить MAX_BOT_TOKEN и пароли PostgreSQL
docker compose up --build -d
```

Это одна команда для сборки и запуска всех обязательных локальных компонентов. При первом запуске PostgreSQL автоматически распакует каталог и применит миграции, а llama.cpp загрузит модели в persistent Docker volumes. Повторный запуск использует volumes и не импортирует данные или модели заново.

Проверка состояния:

```bash
docker compose ps
docker compose logs -f bot
```

Ожидаемый результат: сервис `db` имеет статус `healthy`, в логе `bot` появляется строка `Bot @... started`, после чего бот отвечает в MAX на `/start`.

Остановка и повторный запуск:

```bash
docker compose down
docker compose up -d
```

Данные сохраняются в volume `postgres_data`. Полная очистка локальной БД выполняется только явно: `docker compose down -v`.

## Переменные окружения

Рабочие ключи и пароли не входят в репозиторий. Полный шаблон находится в `.env.example`.

| Переменная | Назначение |
|---|---|
| `MAX_BOT_TOKEN` | токен чат-бота MAX |
| `LLM_BASE_URL` | URL локального chat-сервиса llama.cpp |
| `LLM_API_KEY` | локальный ключ-заглушка |
| `LLM_MODEL` | модель генерации |
| `LLM_TIMEOUT` | таймаут запроса, секунды |
| `LLM_MAX_TOKENS` | предел ответа модели |
| `LLM_LOCAL_MODE` | дополнительные Qwen-специфичные параметры; для Ling — `false` |
| `LLM_USE_JSON_SCHEMA` | отправляет `response_format=json_schema`; для Ling Tiny — `false` |
| `EMBEDDING_BASE_URL` | URL локального embeddings-сервиса llama.cpp |
| `EMBEDDING_API_KEY` | локальный ключ-заглушка |
| `EMBEDDING_MODEL` | embedding-модель |
| `EMBEDDING_DIMENSIONS` | обязательно `1024`, пока схема использует `vector(1024)` |
| `ENABLE_VECTOR_SEARCH` | включает семантический поиск после индексации |
| `POSTGRES_DB` | имя базы |
| `POSTGRES_USER` | пользователь приложения, должен оставаться `maxbot` |
| `POSTGRES_PASSWORD` | пароль пользователя приложения |
| `POSTGRES_ADMIN_PASSWORD` | пароль администратора контейнера PostgreSQL |

По умолчанию запускаются `inclusionAI/Ling-3.0-tiny-GGUF:Q4_K_M` и `smarttasks/Qwen3-Embedding-0.6B-GGUF:Q4_K_M` через отдельные сервисы llama.cpp. Ling Tiny получает JSON-инструкцию, результат дважды валидируется Pydantic и при ошибке запрашивается повторно. Qwen 0.6B возвращает 1024 измерения, то есть полностью совместим со схемой `vector(1024)` и ранее построенным индексом.

При необходимости можно вернуть ProxyAPI: укажите `https://api.proxyapi.ru/v1`, ключ и идентификаторы моделей в `.env`. Для облачного Qwen3 Embedding 4B нужно запрашивать `EMBEDDING_DIMENSIONS=1024`; при смене embedding-модели существующие векторы нельзя смешивать.

## Данные и поиск

В репозитории есть каталог примерно из 30 тысяч курсов и синтетические профили для демонстрации. Миграции создают расписание, академическую историю, выбранные курсы и ограничения целостности. Реальные пользовательские токены, телефоны и диалоги не публикуются.

Сразу после запуска доступен лексический поиск по названиям, темам и ключевым словам. Если уже есть 1024-мерный индекс Qwen 0.6B, его можно перенести в Docker без повторного расчёта. На чистом развёртывании семантический индекс строится отдельно:

```bash
docker compose --profile tools run --rm indexer
```

После успешной индексации установите `ENABLE_VECTOR_SEARCH=true` в `.env` и выполните `docker compose up -d --force-recreate bot`. Индексатор возобновляемый: неизменившиеся документы повторно не отправляются.

## Проверка решения

Модульные тесты не требуют сети или PostgreSQL:

```bash
python -m unittest discover -s tests -v
```

Полный набор, включая интеграционные тесты, запускается внутри контейнера против поднятой Docker-БД:

```bash
docker compose up -d db
docker compose run --rm --no-deps -e RUN_DB_TESTS=1 -v "$PWD:/app" bot \
  python -m unittest discover -s tests -v
```

Ручной сценарий проверки:

1. Отправить `/start` и поделиться контактом.
2. Выбрать демонстрационный профиль.
3. Проверить пункты «Профиль», «История» и «Расписание».
4. Спросить `Посоветуй курс по Python`.
5. Нажать «Добавить в план» и проверить появление курса в прогрессе.
6. Задать уточнение `Почему именно этот?` — агент должен учитывать предыдущую рекомендацию.

## Порты и внешние сервисы

- PostgreSQL использует `5432` только внутри Docker-сети и наружу не публикуется.
- Бот обращается по HTTPS к MAX API (исходящий порт `443`).
- `llm` и `embeddings` используют `8080` только внутри Docker-сети; наружу порты не публикуются.
- При первом запуске Docker скачивает примерно 5.2 ГБ весов в volumes. Это не часть `docker build`, но зависит от скорости сети и может занять более пяти минут.

## Ограничения

- Для доступа к рабочему боту нужен валидный `MAX_BOT_TOKEN`; публичный токен в репозиторий не добавляется.
- Используется long polling. Для постоянной production-инсталляции предпочтителен HTTPS webhook.
- Смена размерности embedding-модели требует миграции `course_embeddings` и полной переиндексации.
- Первый импорт каталога заметно дольше последующих запусков, но не является частью сборки образа.
